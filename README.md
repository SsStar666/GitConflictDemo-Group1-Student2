# GitConflictDemo-Group1

Practical 4 - **Collaborating with GitLab and Resolving Merge Conflicts**.

This is the shared Android Studio project used by the group. It contains a very small
application (one screen with two buttons) that exists for one reason: to let two students
change the *same lines of the same XML file* in two different branches, so that merging the
second branch produces a real merge conflict that the group has to understand and resolve.

## The application

| Item | Value |
|---|---|
| Application ID | `com.example.gitconflictdemo` |
| Screen | `app/src/main/res/layout/activity_main.xml` |
| Widgets | `btnPrimary`, `btnSecondary` (`Button`, tinted with `android:backgroundTint`) |
| Initial button colour | `#6750A4` (Material purple) |
| Entry activity | `MainActivity` |

## Branches

| Branch | Owner | Change |
|---|---|---|
| `main` | shared | Initial application, then both features merged in |
| `feature-red-button` | Student 1 | Both buttons tinted `#F44336` (red) |
| `feature-green-button` | Student 2 | Both buttons tinted `#4CAF50` (green); also carries the merge conflict resolution |

The conflicting file is `app/src/main/res/layout/activity_main.xml`, and the conflicting
lines are the two `android:backgroundTint` attributes (one for each button).

### History shape

```
main                     o---o----------M1------------------M2   (final, green buttons)
                          \            /  \                /
feature-red-button         o---R -----/    \              /
                                            \            /
feature-green-button                          o---G --C--/      (C = Resolve button color
                                                                     merge conflict)

R  = "Change button color to red"      (Student 1)
G  = "Change button color to green"    (Student 2)
C  = "Resolve button color merge conflict" (Student 2, merge commit)
M1 = merge request !1: feature-red-button -> main
M2 = merge request !2: feature-green-button -> main
```

Because Student 1's branch is merged first, `main` already contains the red tint when the
green branch is merged. Git cannot decide between `#F44336` and `#4CAF50`, so it stops with a
conflict. The group reviewed both versions and kept Student 2's green implementation as the
final design; the conflict markers were removed, the XML validated and the app tested before
the resolution was committed.

## Opening the project

1. Clone the repository (or open the folder directly in Android Studio).
2. Open it with **Android Studio 2026.1.3** or newer. The project uses the Android Gradle
   plugin 9.3.0 and the Gradle 9.5.0 wrapper, and targets `compileSdk`/`targetSdk` 37 with
   `minSdk` 24.
3. Let Gradle sync. `local.properties` is generated by Android Studio and is intentionally not
   tracked by Git.
4. Run the `app` configuration on an emulator or device.

Command line build:

```
./gradlew assembleDebug      # macOS / Linux
gradlew.bat assembleDebug    # Windows
```

The debug APK is written to `app/build/outputs/apk/debug/app-debug.apk`.

## Project group

The group name used by this project is `Group1`. To use another group name, update the
application label in `app/src/main/res/values/strings.xml`, `rootProject.name` in
`settings.gradle.kts` and the title of this file.
